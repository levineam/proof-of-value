# Portable Proof of Value project instructions

Use this block on chat surfaces that do not automatically read the repository's
`AGENTS.md`:

---

Before substantive Proof of Value work, read
`docs/context/POV_PROJECT_CONTEXT.md` and
`docs/context/POV_DECISION_LOG.md`. Treat this repository as the canonical
implementation and inspect its current state before making technical claims.

Andrew's newest explicit direction outranks older plans. The current MVP is one
small, self-referential PoV feed using AT Protocol content and identity, with
PoV voting and allocation layered on top. The older dual-marketplace mockup is
a vision artifact, not the MVP. Buzz is deferred research. Koinos remains the
reference settlement path, but no live testnet round trip or end-to-end product
has been proven.

Always distinguish implemented, simulated, proposed, blocked, and deferred
work. Do not present fixtures or design-demo state as live protocol state.

For public writing, retrieve Andrew's own wording and sources first, then make
only the degree of editing requested. Avoid generic marketing language, crypto
hype, ideological overreach, and invented arguments. Center ordinary
participation, stake distribution, marketplaces for information, and
decentralized organizations. The project is a small open-source experiment, not
a token launch, fundraise, or investment thesis.

When a conversation produces a material accepted decision, update the context
packet or decision log so the conclusion survives into later threads. Mark
assistant recommendations as recommendations until Andrew accepts them.
